# VPS Drop Sync

通用 VPS 放货精准对时与自动抢购助手。

VPS Drop Sync 是一个 Tampermonkey 用户脚本，适用于采用相同购物车接口的 VPS/服务器销售网站。它会复用浏览器当前登录状态，在指定时间轮询一个或多个商品 PID，自动解析商品配置表单并尝试完成加购和结账。

> 原适配网站已经停止运营，因此项目已改造成不绑定服务商品牌的通用版本。是否兼容取决于目标网站的购物车接口，而不是网站名称。

## 一键安装

[点击安装 VPS Drop Sync](https://raw.githubusercontent.com/1Beyond1/VPS-Drop-Sync/main/vps-drop-sync.user.js)

安装前请先准备 Tampermonkey、Violentmonkey 等用户脚本管理器。

## 核心亮点

### 二段式服务器精准对时

本项目针对“本机时间和服务商放货时间存在偏差”的问题做了专门优化：

1. 启动任务时立即进行第一段校时，连续采样 3 次，用于修正初始倒计时。
2. 开抢前 60 秒执行第二段精校，连续采样 5 次。
3. 每次请求都记录发送时间、接收时间和服务器 Date 响应头，使用网络往返时间中点估算服务器时间差。
4. 按 RTT 排序并去掉两端样本，再对剩余结果取平均，降低网络抖动和异常请求的干扰。
5. 最后 5 秒将倒计时检查频率提高到 50ms，减少浏览器定时器造成的启动延迟。

界面会实时显示校准后的服务器时间偏差和平均 RTT。需要注意，HTTP Date 响应头通常只有秒级精度，代理/CDN 也可能改写它，因此该机制只能减少时间误差，不能保证绝对毫秒级准确。

### 其他功能

- 支持多个 PID，按顺序循环探测。
- 自动复用当前浏览器 Cookie，无需手动复制登录凭据。
- 动态解析商品配置表单，不依赖固定套餐字段。
- 支持支付宝、微信支付和 PayPal 选项。
- 可设置自动开始和自动停止时间。
- 支持 500ms、100ms 和 10ms 三档重试频率。
- Wake Lock 防止等待过程中设备休眠。
- 跨页面保存最近 100 条运行日志。
- 成功后自动跳转到账单或支付页面。

## 配置服务商网址

脚本不会默认在任何网站显示控制面板。首次使用时：

1. 安装脚本。
2. 登录目标 VPS 服务商网站。
3. 点击浏览器工具栏里的 Tampermonkey 图标。
4. 在脚本菜单中选择“在当前网站启用 VPS Drop Sync”。
5. 刷新网页，右上角会出现控制面板。

脚本按完整主机名保存白名单。例如，在 panel.example.com 上启用，并不会自动在 www.example.com 上启用。如果服务商的商品页和结账页位于不同子域名，需要分别启用。

需要停用时，在对应网站的 Tampermonkey 菜单中选择“在当前网站禁用 VPS Drop Sync”。

虽然元数据允许脚本匹配 HTTP/HTTPS 网站，但未加入白名单的网站只会注册启用菜单：不会注入操作面板，也不会发送购物车请求。

## 判断网站是否兼容

当前版本面向使用以下同源购物车路径的网站：

~~~text
/cart?action=configureproduct&pid=商品ID
/cart?action=emptycart
/cart?action=viewcart&statuscart=checkout
~~~

商品配置页还需要包含可提交的 form、input 和 select 字段。部分 WHMCS 或二次开发的销售系统可能兼容，但不能仅凭页面外观判断。

建议先使用一个正常有货、价格较低的测试商品验证完整流程。如果服务商更改了接口、字段、风控或验证码，脚本需要针对该网站重新适配。

## 如何找到服务器 PID

PID 是商品在购物车系统中的数字 ID。控制面板支持填写一个或多个 PID，例如：

~~~text
2159
2159,2160,2168
~~~

### 方法一：修改地址中的 PID 逐个查看

先在服务商网站随便点击一个服务器或套餐，观察地址栏。常见地址类似：

~~~text
https://panel.example.com/cart?action=configureproduct&pid=2159
~~~

找到 pid= 后面的数字，然后修改这个数字并访问：

~~~text
https://panel.example.com/cart?action=configureproduct&pid=2160
https://panel.example.com/cart?action=configureproduct&pid=2161
~~~

如果打开后显示的是你想要的配置，即使当前提示缺货，也可以记下这个 PID。若跳回首页、显示商品不存在或进入完全不同的套餐，则继续尝试其他数字。

### 方法二：第一次放货只记录 PID

如果不知道目标商品的 PID，可以在第一次放货时先不急着购买：

1. 在商品出现后点击进入配置页。
2. 从地址栏、购买按钮链接或浏览器开发者工具的 Network/网络请求中记下 pid 数字。
3. 将 PID 保存下来。
4. 等下一次补货前，把 PID、开始时间、停止时间和支付方式提前填好。
5. 至少提前两分钟启动脚本，让“启动初校”和“开抢前 60 秒精校”都能执行。

这种方式比临近放货时盲猜 PID 更可靠。

## 使用方法

1. 登录已经启用脚本的服务商网站。
2. 输入目标商品 PID；多个 PID 使用逗号、空格或竖线分隔。
3. 设置自动开抢时间，精确到秒。
4. 设置自动停止时间，避免长时间持续请求。
5. 选择支付方式和重试频率。
6. 点击“启动定时 / 立即抢购”。
7. 保持页面和网络连接正常，成功后检查订单与账单。

建议默认使用 500ms 安全模式。100ms 和 10ms 会显著增加请求量，可能触发限流、验证码、账号限制或 IP 封禁；使用前必须了解并遵守服务商规则。

## 工作流程

~~~text
读取配置
  → 启动初校（3 次采样）
  → 开抢前 60 秒精校（5 次采样）
  → 到达服务器校准时间
  → 清空购物车
  → 按 PID 探测库存
  → 动态解析配置表单
  → 提交加购
  → 提交结账
  → 验证账单页面
  → 跳转支付
~~~

## 注意事项

- 仅在你有权使用的账户和服务商网站上运行。
- 请遵守目标网站服务条款、购买限制和请求频率限制。
- 脚本不能绕过验证码、登录验证、支付确认或服务端风控。
- 不同服务商可能使用不同结账字段，务必先测试兼容性。
- 自动化下单可能产生真实订单、重复订单或付款义务，请设置停止时间并及时核对。
- 抢购结果仍受库存、网络延迟、服务器负载和风控策略影响。
